Implementation report

From a generated list to an accepted, persistent calendar plan.

The submission build replaces placeholder scheduling and immediate saving with a validated recommendation workflow, reliable storage, draggable time controls, and explicit AI fallback behavior.

30 minCalendar snap and preview lifetime
2 hoursMaximum duration of one study session
12 secMaximum wait before deterministic AI fallback

Before and after

Recommendation flow

BeforeGenerate and save tasks immediately.
AfterCreate a temporary preview, explain it, let the student move sessions, then accept the complete plan.

Scheduling

BeforeAbstract day counters and fixed front-end start times.
AfterReal dates and HH:MM times, 30-minute search, preferred windows, two-hour caps, saved-task conflict avoidance, and deadline capacity checks.

Storage

BeforeIn-memory lists disappear on restart.
AfterGoals and tasks persist in JSON using temporary-file replacement and max-ID-plus-one allocation.

Calendar editing

BeforeMonth view without scheduled events or dragging.
AfterMonth, week, and day views; the 24-hour weekly grid adds pre-accept and post-accept dragging, fixed duration, server validation, and automatic revert on failure.

AI behavior

BeforeContext frozen at import and unhandled local-model failure.
AfterContext is rebuilt per request; Ollama output is time-limited and every fallback is labelled with a reason.

Frontend safety

BeforeDynamic user and AI text inserted through HTML strings.
AfterDynamic content uses text nodes and DOM construction; every request handles HTTP, JSON, and network errors.

API surface

MethodEndpointResponsibility
POST/plan-previewsSchedule without persistence; return sessions, explanation, mode, warning, and expiry.
POST/plan-previews/{id}/acceptRevalidate every adjusted session and atomically save the goal and tasks once.
PATCH/tasks/{id}/scheduleMove a saved task while preserving duration and enforcing conflicts and deadlines.
PATCH/tasks/{id}Keep the existing pending/completed status capability.
POST/chatAnswer from current goals, tasks, and optional preview; expose AI or fallback mode.
POST/generate-planDeprecated compatibility route for older clients.

Validation and tests

Scheduler

Preferred-window placement, maximum duration, overlap avoidance, capacity failure, date handling, and 30-minute boundaries.

Persistence

Preview non-persistence, atomic acceptance, reload survival, sequential IDs, double-accept rejection, and corrupt JSON failure.

Moves

Fixed duration, past time, deadline, saved-task overlap, missing task, and browser revert behavior.

AI and UI

Dynamic context, local-model success mode, timeout/failure fallback, safe text rendering, and end-to-end browser smoke flow.

Deferred intentionally: external-calendar import, timezone conversion, advanced optimization, branding work, and a large visual redesign. These would increase submission risk without strengthening the core demonstration.
